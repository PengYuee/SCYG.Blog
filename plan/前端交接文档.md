## 2. 已完成能力

### API 与请求层

- `backend/api/openapi.yaml` 是唯一 HTTP 契约来源。
- `frontend/src/request/generated/` 由 Hey API 生成 TypeScript 类型和 Zod definitions。
- 生成配置位于 `frontend/openapi-ts.config.ts`，不生成 operation client，适配器继续复用唯一 Axios 实例。
- 文章、taxonomy、图片、登录与 AI 均通过 src/request/api 适配器访问；AI 的共享 Run 生命周期在 services/ai-run.ts，普通请求不另建 Axios。
- 保留响应边界解析、分页转换、`If-Match`、multipart、`204` 和动态 `serverUrl` 行为。

### 认证与作者域

认证入口和状态流转：

1. 应用启动时创建 Pinia、API Services 和认证会话控制器。
2. 从 `localStorage["scyg.auth.session"]` 恢复会话。
3. 恢复时使用生成的 `LoginResponse` Schema 校验令牌结构和 `expiresAt`。
4. 请求边界按 author/anonymous/none 明确选择 Bearer；作者来自统一会话服务，匿名有独立凭证及失效处理，旧401不能污染新会话。
5. 匿名访问 `/author/**` 跳转 `/login?redirect=<站内地址>`。
6. 登录成功后回到原站内地址，缺少合法返回地址时进入 `/author/articles/new`。
7. 过期会话、畸形会话和后端 `401` 会清除本地会话。
8. 作者布局的“退出登录”只清除浏览器会话并返回首页；后端当前没有 refresh、me 或 logout 接口，因此前端不伪造这些能力。

主要入口：

- `frontend/src/services/auth-session.ts`：会话恢复、登录、退出、令牌读取和失效处理。
- `frontend/src/stores/auth.ts`：匿名、恢复中、已认证、已过期状态。
- `frontend/src/request/api/auth.ts`：`POST /api/v1/auth/login` 适配器。
- `frontend/src/request/http.ts`：Bearer 注入和 `401` 失效回调。
- `frontend/src/router/guards.ts`：认证导航守卫和站内 redirect 校验。
- `frontend/src/router/modules/author.ts`：统一 `requiresAuth` 作者路由边界。
- `frontend/src/views/public/LoginView.vue`：登录页面。

### AI 业务与恢复

作者入口为 `/author/ai` 及其 Run 页，公共入口为 `/ai/search` 及其 Run 页。四能力表单、结果、人工交互、错误与主体恢复规则集中见 [AI 使用说明](../docs/services/frontend/ai.md)，服务端范围／预算／Redis配置见 [公共控制](../docs/services/agent/public-search.md)。本轮不向编辑器回填、不自动保存或发布。

AI 源码、生成合同及本轮真实模型结果已经到位，未保留占位页、JSON业务表单或直接Provider入口。前端check:api改为临时目录生成对比工作区，不依赖暂存。完整最新检查、OCR覆盖和环境限制在本轮任务记录维护，交接时只引用正式机制，不复制原始日志。

## 3. 验收状态与未完成事项

### 3.1 管理后台尚未实现

当前 `/admin` 及其子路径统一呈现“管理后台暂不可用”。后续若实施，应单独立项，至少覆盖：

- 管理路由和页面范围；

- 管理端浏览器验收和权限失败结果。

不要把管理后台实现混入认证修复或 API 生成收口任务。

### 3.2 E2E 认证断言已迁移

`frontend/tests/e2e/t13/` 已删除认证不可用的旧断言。生产路由验收验证匿名深链及旧写作地址的登录跳转，`auth-session.spec.ts` 覆盖：

- 匿名访问作者深链跳转登录页，并保留 `redirect`；
- 登录失败显示后端错误，且密码输入被清空；
- 登录成功进入作者页面；
- 受保护请求携带 Bearer Token；
- 退出登录清除会话；
- 会话过期后重新要求登录；受保护请求返回 `401` 后清除会话，下一次作者导航重新要求登录。

公共读取 fixture 已同步独立的公共分类/标签契约；管理字典 fixture 用于作者页面，方法隔离与写阻断规则见[开发指南](../docs/services/frontend/development.md#验证命令)。本任务前端应用变更已通过 `pnpm check`；本轮生产构建成功，审查修复后的预构建 t13 在三个 Edge 桌面视口下为 93 通过、3 外部参考未配置跳过。自动化 API fixture 验收与下面的真实后端联调分别记录，不相互替代。

## 5. 验证命令

在 `frontend/` 目录执行：

```powershell
$env:CI = ""
pnpm check
pnpm test:e2e:production
```

`pnpm test:e2e:production` 会先构建，再运行 t13 的三个 Edge 桌面视口。普通 `pnpm test:e2e` 不包含 t13。

`pnpm check` 覆盖 API 生成无漂移、类型检查、单元测试、组件测试和生产构建。认证改动的最小定向验证：

```powershell
pnpm typecheck
pnpm test:unit
pnpm test:component
pnpm build
```

真实后端联调需要 Microsoft Edge 和可用后端，不应只依赖 Vitest 或 mock 响应。

## 6. 关键约束

- 不在页面、Store 或组件中创建第二个 Axios 客户端。
- 不直接导入生成 client；当前生成层只提供类型和 Zod definitions。
- 不手工修改 `src/request/generated/`。
- 不把 JWT payload 当作前端可信权限来源；最终认证和授权由后端负责。
- 不在前端伪造 refresh、me、logout 或管理员权限。
- API 字段、路径、状态码和错误结构以 `backend/api/openapi.yaml` 为准。
- 认证会话只保存短期登录响应；错误信息不得主动打印密码或访问令牌。
