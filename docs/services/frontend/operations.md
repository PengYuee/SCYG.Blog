# 前端部署与运行手册

## 运行结论

前端源码位于 [`frontend/`](../../../frontend/)，本文源码与构建路径均相对于该目录。前端部署物是 Vite 生成的静态单页应用。部署环境必须同时提供：

1. `dist/` 中的 HTML、JavaScript、CSS 和静态资源；
2. 同源 `/config.json`；
3. 对客户端路由的 SPA history fallback；
4. 浏览器可访问的后端 HTTP(S) 地址。

仓库当前没有前端容器、Web Server、CDN 或发布流水线配置。本文定义应用可确认的部署契约，不宣称某个托管平台已经实现这些要求。

## 构建产物

在 `frontend/` 目录安装锁定依赖并执行生产构建：

```powershell
pnpm install --frozen-lockfile
pnpm build
```

`pnpm build` 先运行 `vue-tsc -b`，再由 Vite 输出 `dist/`。构建失败时不得发布旧目录与新配置的混合结果。

`public/` 下的文件由 Vite 复制到构建根目录，因此仓库中的 `public/config.json` 会成为 `dist/config.json`。部署流程可以在构建后替换该文件，从而为不同环境设置后端地址，无需重新编译 JavaScript。

## 运行时配置契约

`/config.json` 的唯一当前字段是：

```json
{
  "serverUrl": "https://api.example.test"
}
```

约束：

- 响应必须是成功状态和有效 JSON；
- 顶层必须是对象，不能包含未声明字段；
- `serverUrl` 必填，必须是绝对 HTTP(S) URL；
- 末尾单个 `/` 会在浏览器内归一化移除；
- 浏览器请求配置的超时为 10 秒；
- 配置必须在页面加载时可用，应用不会用编译期地址兜底。

若前端与 API 不同源，后端或其网关必须允许浏览器跨域请求。实际允许来源、凭据和缓存策略由部署平台与后端共同维护，前端仓库当前没有对应配置。

AI 的普通请求与 SSE 使用同一个 serverUrl，包括部署路径前缀；网关须转发 Bearer、Idempotency-Key 和 opaque Last-Event-ID，保留 SSE 的持续连接及错误响应，向浏览器暴露 Retry-After。浏览器不连接 Agent/Redis/Provider。后端启用及公共控制前提见 [Agent 公共搜索控制](../agent/public-search.md)，作者操作和匿名凭证恢复见 [AI 使用说明](ai.md)。

建议让 `config.json` 使用可及时刷新的缓存策略，并让带内容哈希的构建资源使用长期缓存；这是部署建议，不是仓库内已经实现的托管配置。

## 静态托管要求

前端使用 `createWebHistory`。托管方应按以下优先级处理请求：

1. 存在的静态文件按原路径返回，例如 `/assets/**`、`/favicon.svg`、`/config.json`；
2. 其他前端页面路径返回 `index.html`，由 Vue Router 解析；
3. 不得把缺失的 `config.json` 回退成 `index.html`，否则浏览器会把 HTML 判定为无效配置。

至少验证直接打开以下地址不会得到托管层 404：

- `/`
- `/articles`
- `/articles/<有效文章标识>`
- `/admin`
- `/ai/search` 与 `/ai/search/runs/<当前匿名主体任务标识>`
- `/author/ai` 与 `/author/ai/runs/<当前作者任务标识>`

作者路径需要后端签发的有效短期 Bearer 会话；匿名深链由应用跳转到 `/login`。

## 发布步骤

1. 在干净依赖状态下执行 `pnpm install --frozen-lockfile`。
2. 执行 `pnpm check`，确认类型检查、单元测试、组件测试和构建通过。
3. 保留本次 `pnpm build` 生成的完整 `dist/`，不要与旧版本文件合并。
4. 按目标环境写入 `dist/config.json`，保持字段名和 JSON 类型不变。
5. 将同一批次的完整静态产物部署到托管方。
6. 按下节执行浏览器发布验证。
7. 验证完成前保留上一批完整产物及其配置，以便原子回滚。

仓库当前没有前端 CI 工作流；以上步骤需要由实际发布系统落地后，才能把流水线状态作为发布证据。

## 发布验证

### 配置与启动

1. 请求 `/config.json`，确认返回 2xx、JSON 内容和目标 `serverUrl`。
2. 打开 `/`，确认页面没有出现“运行时配置加载失败，请检查 config.json 后重试。”。
3. 在浏览器 Network 中确认公共 API 请求发送到预期后端。

### 路由

1. 直接打开 `/articles`，确认托管方返回应用而不是 404。
2. 直接打开一个有效文章详情地址，确认刷新后仍能进入详情页面。
3. 打开 `/admin`，确认由应用呈现管理后台不可用状态。
4. 打开未知非管理地址，确认由公共 404 页面处理。

### 生产认证边界

1. 匿名打开作者地址，确认跳转 `/login` 且 `redirect` 保留原站内地址。
2. 使用目标后端的活动用户登录，确认返回作者页面，并在受保护请求中发送 Bearer Token。
3. 退出登录后确认 localStorage 会话被删除，再次访问作者地址会重新要求登录。
4. 检查目标 Microsoft Edge 桌面视口；当前支持下限为 `1024px`。

### 真实作者写入

1. 准备活动账号及明确允许写入的测试分类、标签和文章，不覆盖既有业务内容。
2. 在作者 UI 创建含多段 Markdown 的草稿，确认保存成功后自动进入编辑地址；刷新后标题、slug、分类、标签及原始正文保持一致。
3. 修改并保存，确认版本递增、刷新保留修改；不要用无变化保存代替修订验证。
4. 上传图片后保存正文引用，再刷新并确认实际图片可见，媒体请求不携带 Bearer 也返回 200；上传成功或正文包含 URL 本身不能证明图片已提交。
5. 退出并重新打开作者深链，确认会话清除、登录跳转及原站内 `redirect`。没有发布或删除授权时保留测试草稿和图片。

### 真实 AI 链路

使用专用账号和标记数据，分别从作者工作台发起四能力，观察真实 Run、SSE 与结果；写作启用两项准备时逐次提交文本、参考选择和最终确认。匿名公共搜索须在无作者登录的 tab 创建、刷新恢复，实际模型输入及引用只能使用公开内容。

验证丢失响应、离页、断线、取消、错误输入和账号隔离时，按 [AI 任务](../../modules/ai-assistance.md)与[公共搜索](../../modules/public-ai-search.md)的现行规则判断结果。复制结果不能改另页未保存草稿；不能以 fixture、HTTP 200 或旧回执代替目标部署环境的真实运行。

### 自动化生产验收

如需运行仓库内的预构建产物验收：

```powershell
pnpm build
pnpm test:e2e:production
```

该命令使用本地 Microsoft Edge，并只运行 `tests/e2e/t13`；API 响应使用受控 fixture。它不是对真实后端、生产域名、网关或 CDN 的验收，目标环境仍须完成上述活动用户登录与写入验证。

## 故障处理

| 现象 | 直接检查 | 处理 |
| --- | --- | --- |
| 页面显示运行时配置错误 | `/config.json` 状态、内容类型、JSON、`serverUrl` | 恢复有效配置；不需要重新构建 JavaScript。 |
| `/config.json` 返回 HTML | 托管 fallback 顺序 | 将真实文件匹配放在 SPA fallback 之前。 |
| 首页可开，刷新子路由 404 | Web Server 或 CDN 路由规则 | 为非静态文件的页面请求配置 `index.html` fallback。 |
| 页面启动但列表或详情请求失败 | Network 中目标 URL、CORS、后端状态 | 修正 `serverUrl`、跨域策略或恢复后端。 |
| API 返回成功但页面拒绝数据 | 响应结构与前端 Zod Schema | 对齐后端响应和 `src/request/api/` 当前契约，不在页面绕过校验。 |
| 登录后立即返回登录页或受保护请求返回 `401` | 登录响应、令牌过期时间、后端 JWT 配置和浏览器 Network | 对齐后端认证配置；不要在前端伪造 refresh 或延长令牌。 |
| 新版本样式或脚本不一致 | HTML 与哈希资源是否来自同一批次 | 原子替换完整产物并清理错误缓存，不单独拼接版本文件。 |

## 回滚

回滚单位是“完整静态产物 + 与该版本兼容的 `config.json`”。不要只回滚 `index.html`、单个脚本或配置的一部分。

1. 停止继续分发故障版本。
2. 恢复上一批完整构建目录及其运行时配置。
3. 重新执行配置、首页、直接子路由和公共 API 验证。
4. 确认浏览器不再引用故障版本的哈希资源。

前端没有数据迁移职责；若故障来自后端接口不兼容，应由接口所有者决定后端回滚或兼容策略，前端手册不推断下游内部恢复步骤。
